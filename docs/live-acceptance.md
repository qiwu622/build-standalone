# 独立 Google 真实验收清单

本清单是完整验收范围，不表示所有项目均已通过。0.5.0 已在用户授权的 Windows 新安装中完成部分真实 Google 调用，具体结果和未覆盖范围见 [验证记录](validation.md)。其他环境仍需自行登录可用 Google AI 订阅账号；完成登录后，只有明确同意测试生成才发起以下调用，测试会消耗该账号额度。

1. 全新安装，确认生成的 API/admin 密钥独立、监听地址正确，打开管理页。
2. 在常用 Chrome／Edge 加载或更新 `extensions/build-browser-bridge`，打开本机管理页，点击“登录并自动接入”。正常完成 Google 官方账号选择和二步验证；确认登录时未挂接调试器。首次应只提交一次最小专用项目初始化（会消耗额度），之后自动登记；再次接入必须复用同一项目、不再初始化。核对邮箱、账号索引及在线状态。
3. 分别用两个基础模型的 low/medium/high 与无后缀发起短文本请求；核对网页及 RPC 模型/原生 thinking 元数据，不把提示词内容当证明。
4. 普通模型发送系统指令、历史及当前消息，验证每次新建聊天、一份原生聊天附件和短输入指令；至少一次包含 Unicode、空白和首中末检查值的长历史，并确认下一次请求没有旧附件。酒馆专用模型仍检查预设在输入框、历史和世界书在项目文件，以及完成后的项目文件清理。
5. 验证无校验暗号的正文、拒答说明均原样返回；有本次精确旧版前缀时只去掉前缀。JSON 和 SSE 都必须保留完整正文，不为补暗号重试。
5. 检查 SSE 只在完整答案后返回正文、stop 与 DONE；不以此作为真流式验证。
6. 通过客户端取消一个独立测试请求，核对网页停止和文件清理；再发一次正常请求确认串行调度恢复。
7. 多账号轮换的故障路径先由离线注入测试验证；不为验收刻意耗尽真实账号额度。不重放上游已拒绝内容。
8. 验证浏览器关闭、调试连接被取消、服务重启和账号切换后的明确失败及重新配对。Linux 桌面另行验收；无桌面服务器不属于本版扩展模式的已验证范围。

记录平台、版本、时间、测试项目、状态和必要的脱敏元数据。禁止保存密码、Cookie、密钥、真实聊天正文或完整网络抓包到发布证据。失败应明确停在该层，不自动改用其他模型或其他会话。
