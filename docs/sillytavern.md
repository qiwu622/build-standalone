# SillyTavern 预设与背景分流

适配器支持酒馆自定义 OpenAI 连接，已针对 SillyTavern 1.13.2 的本地链路验证。客户端扩展和 Build Standalone 0.2.0 必须配套使用，不会自动升级任何其他聚合网关。

## 安装和选择

在独立版解压目录运行（用户目录以实际安装为准）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-sillytavern.ps1 -UserDirectory 'D:\SillyTavern\SillyTavern\data\default-user'
```

也可将 `extensions/build-standalone-adapter` 整个目录复制到酒馆的实际 `data/<用户>/extensions/` 下。安装脚本只复制扩展，已有版本会备份到该用户的 `backups/`；不修改酒馆核心、连接、预设、历史或密钥。刷新酒馆，在扩展设置里可看到“Build 独立版 · 酒馆分流”。

为独立网关新建自定义 OpenAI 连接，填写其 `/v1` 地址和 API 密钥。选择 `build-st/gemini-4-argon-low`、`-medium`、`-high`，或对应 Flash 模型。没有后缀时固定 high。普通 `gemini-*` 或 `build/*` 模型沿用普通接口行为。

关闭“合并系统消息（Squash system messages）”，清空此连接的自定义请求正文和排除正文参数。只支持纯文本单候选，不支持图片、工具调用或 JSON schema。

## 每次请求怎么处理

1. 在酒馆宏展开后的临时副本中记录来源。Prompt Manager 的启用预设、主提示词、后历史指令等直接进入 Build 输入框，包括以 user/assistant 角色插入的预设。
2. 历史、角色资料、世界书、作者注释、摘要、向量检索内容等进入两个请求专属 JSONL 文件。一个保存顺序、角色和来源索引，另一个保存分片正文。预设正文不会写入这两个文件。
3. 本轮用户消息与酒馆原始聊天转换结果完全匹配时也进输入框。其他扩展若改写了这条消息且无法准确识别，它会完整保留在文件中，不会根据 user 角色误把世界书当作当前问题。
4. 保留每条消息的角色、名称、次序、Unicode 和空白；角色扮演、续写和代写请求保留生成类型。生成前新开聊天，使用本次 API 请求的内容；不继承上次 API 的历史。
5. Google 回复必须带本次文件末尾校验值才能返回正文，随后清理文件。校验值证明读到了文件末尾，不能证明模型在语义上理解了每一段。

表格等扩展在来源核对前额外插入的消息，只要原消息仍完整且顺序不变，就作为背景进入文件。若其他扩展改写/合并了原消息、在来源核对后修改消息，或协议不兼容，会在 Google 调用前报错。ST 事件监听器会吞掉异常，因此扩展发送明确的错误封装，由独立网关拒绝；不会靠抛异常后继续发送未经分流的长文本。

## 限制

- 45000 token 是当前适配器设置的**本地估算阈值**，不是 Google 官方保证。酒馆 tokenizer 与 Google 计数不同，输入框还包含少量文件读取/顺序说明；接近边界时应留余量。超过阈值直接报错，不偷偷截断或把预设改放文件。
- 酒馆自身的上下文预算仍然有效。在扩展收到消息以前，酒馆可能已经按其预算裁减历史；扩展不能恢复被酒馆删掉的内容。临时来源标记也参与酒馆估算，建议给上下文预算留余量。
- 本扩展仅对 `build-st/` 专用模型生效；该模式会明确去掉 Build 网页不支持的 temperature、top_p、stop 等参数。思考强度由模型名后缀控制。
- 文件方式不会扩大模型的总上下文上限，也不保证原生多角色 API 的效果。独立版仍是完整生成后返回 SSE，未新增真正的逐 token 流式能力。
- 本地拆分与假执行器测试不等于 Google 实际读取和生成通过。Google 实际账号测试需要在自己的环境另行验收。

扩展只展示分段数量、字符数和 token 估算，不打印预设正文。源码发布包不包含用户提供的预设、账号或聊天数据。
