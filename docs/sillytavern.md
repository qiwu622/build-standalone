# SillyTavern 预设与背景分流

0.5.0 已将分流并入浏览器连接器。只需安装 `extensions/build-browser-bridge` 一个扩展，在同一浏览器打开 Build 和酒馆。当前适配 SillyTavern 1.13.2。

## 启用和迁移

1. 加载或重新加载浏览器连接器，然后刷新酒馆。
2. `http://localhost` / `http://127.0.0.1` 下的酒馆自动启用，不限制端口。局域网或其他域名：在酒馆页面打开连接器弹窗，点“在当前酒馆站点启用”，仅授权该站点。
3. 酒馆扩展设置中显示“Build 独立版 · 酒馆分流”，版本 0.5.0（浏览器连接器内置）。勾选“直接读取当前启用预设”。
4. 已安装旧 Build 酒馆扩展的用户：在酒馆“管理扩展”中禁用旧版，再刷新。连接器检测到旧版仍在运行时会让旧版单独处理，防止重复包装。

不需要在酒馆内再次安装 GitHub 扩展，也不用安装油猴。仓库根 manifest 和旧安装脚本保留作为兼容入口，不是新版安装的必需步骤。

连接可选“自定义 OpenAI”，填写独立网关的 `/v1` 地址和 API 密钥；也可继续使用“OpenAI”，将同一地址填入反向代理地址，API 密钥填入该反向代理的密码字段。选择 `build-st/gemini-4-argon-low`、`-medium`、`-high`，或对应 Flash 模型。没有后缀时固定 high。普通 `gemini-*` 或 `build/*` 模型沿用普通接口行为。

允许“合并系统消息（Squash system messages）”；自定义连接需清空自定义请求正文和排除正文参数。只支持纯文本单候选，不支持图片、工具调用或 JSON schema。安装/更新后刷新酒馆，确认面板显示版本 0.5.0（浏览器连接器内置）；无需重新登录 Google。

## 每次请求怎么处理

1. 接入酒馆 Prompt Manager 处理启用预设的步骤，在宏已展开的临时副本上标记预设；不复制关闭的备用项，也不重新执行宏。主提示词、后历史指令等进入 Build 输入框，包括以 user/assistant 角色插入的预设。
2. 历史、角色资料、世界书、作者注释、摘要、向量检索内容等进入两个请求专属 JSONL 文件。一个保存顺序、角色和来源索引，另一个保存分片正文。预设正文不会写入这两个文件。
3. 本轮用户消息与酒馆原始聊天转换结果完全匹配时也进输入框。其他扩展若改写了这条消息且无法准确识别，它会完整保留在文件中，不会根据 user 角色误把世界书当作当前问题。
4. 保留每条消息的角色、名称、次序、Unicode 和空白；角色扮演、续写和代写请求保留生成类型。生成前新开聊天，使用本次 API 请求的内容；不继承上次 API 的历史。
5. Google 回复必须带本次文件末尾校验值才能返回正文，随后清理文件。校验值证明读到了文件末尾，不能证明模型在语义上理解了每一段。

发送时，扩展从最终消息直接提取标记内的启用预设，其余文本统一作为背景。保留最终消息顺序、角色和文字，因此预设宏展开、advice 注入、消息合并、插入和后期修改不再与旧的来源树做逐字核对。也不再缓存和匹配预览准备记录。标记只存在于临时副本，发送前移除，不写回已保存的预设或聊天。

若显示“尚未读取到本次酒馆预设”，先刷新酒馆再正常发送聊天。酒馆的“测试连接”不经过预设准备流程，请用普通 `gemini-*` 模型测试；这仍是实际模型调用，可能消耗额度。若其他扩展破坏了预设标记本身，仍会提示边界损坏，避免混入标记文字或错放预设。ST 事件监听器会吞掉异常，因此此类异常通过明确的错误封装交给网关拒绝，不会继续调用 Google。

## 限制

- 45000 token 是当前适配器设置的**本地估算阈值**，不是 Google 官方保证。酒馆 tokenizer 与 Google 计数不同，输入框还包含少量文件读取/顺序说明；接近边界时应留余量。超过阈值直接报错，不偷偷截断或把预设改放文件。
- 酒馆自身的上下文预算仍然有效。在扩展收到消息以前，酒馆可能已经按其预算裁减历史；扩展不能恢复被酒馆删掉的内容。临时来源标记也参与酒馆估算，建议给上下文预算留余量。
- 本扩展仅对 `build-st/` 专用模型生效；该模式会明确去掉 Build 网页不支持的 temperature、top_p、stop 等参数。思考强度由模型名后缀控制。
- 文件方式不会扩大模型的总上下文上限，也不保证原生多角色 API 的效果。独立版仍是完整生成后返回 SSE，未新增真正的逐 token 流式能力。
- 2026-10-29 已用真实酒馆、自定义连接、Izumi 1029 和 `build-st/gemini-4-argon-high` 验收。0.3.0 直接读取预设流程额外完成一轮带历史调用，约 97 秒返回历史校验字符串和 `PRESET_DIRECT_OK`；文件校验及清理成功。此结果不代表所有第三方扩展或长上下文组合都已验收。

扩展只展示分段数量、字符数和 token 估算，不打印预设正文。源码发布包不包含用户提供的预设、账号或聊天数据。
